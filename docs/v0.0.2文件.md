
Kitty IDE - 项目与文件系统设计文档

版本：0.0.2
状态：设计已确认，待开发
更新时间：2026-09-26

---

一、核心理念

Kitty IDE 采用“文件夹即项目”的设计思路。项目本质就是一个包含源码、资源和 .kitty_project.json 元数据的文件夹。不强制校验目录结构，给用户最大的自由度，同时为未来支持多语言和多媒体文件留出空间。

---

二、项目操作流程

1. 打开项目（Open Project）

流程：

1. 用户点击启动页的「打开项目」按钮。
2. 触发 Android SAF 的 OpenDocumentTree，让用户选择一个文件夹。
3. 不进行任何合法性校验，选什么就进什么（哪怕文件夹是空的）。
4. 获取并持久化该文件夹的 URI 权限（takePersistableUriPermission），确保下次进入 App 还能读写。
5. 跳转到编辑器页面。
6. 写入最近项目记录（见下文）。

文件树展示规则：

· 展示目录下的所有文件和文件夹（不限制类型），因为未来需要支持图片、配置文件等。
· 点击文本文件（.html / .js / .css）：在编辑器中打开。
· 点击其他文件（如图片、二进制文件）：暂时弹 Toast 提示“暂不支持预览此格式”，但文件树中正常显示，留作后续扩展。

2. 新建项目（New Project）

流程：

1. 用户点击启动页的「新建项目」按钮。
2. 弹出「新建项目」对话框，包含以下输入项：
   · 项目名（必填，作为文件夹名）
   · 初始版本（必填，默认 v0.0.1）
   · 项目描述（选填）
   · Program language（编程语言）（下拉框，0.0.2 版本提供：Web）
   · 复选框：[ ] 创建示例文件（勾选后自动生成基础 index.html）
3. 用户点击确认后，触发 SAF 的 OpenDocumentTree 选择父目录。
4. 在选中的父目录下，创建一个以「项目名」命名的子文件夹。
5. 在该子文件夹内自动生成 .kitty_project.json。
6. 若勾选了「创建示例文件」，则同时生成一个包含基础结构的 index.html。
7. 跳转到编辑器页面，并写入最近项目记录。

3. 最近项目（Recent Projects）

位置：
存储在 Kitty IDE 自身的私有目录中（context.filesDir/projects.json），不污染用户的文件夹。

写入时机：
每次成功打开或新建项目后，自动更新这个文件（如果已存在则更新时间并置顶，不存在则新增）。

启动页展示：
启动页在“新建/打开”按钮下方，展示最近打开的项目列表，点击即可直接进入。

三、项目元数据规范（.kitty_project.json）

每个项目根目录下自动生成此文件。

数据结构（JSON）：

```json
{
  "project_name": "我的第一个网站",
  "project_version": "v0.0.1",
  "ide_version": "0.0.2",
  "description": "这是一个练习用的网站",
  "main_language": "Web",
  "created_at": "2026-09-26T12:48:00Z"
}
```

字段说明：

字段 类型 说明
project_name String 项目显示名（可与文件夹名不同，后续支持重命名）
project_version String 项目初始版本（用户输入）
ide_version String 创建该项目时的 Kitty IDE 版本号（自动填入）
description String 项目描述（选填，可为空）
main_language String 主要编程语言（0.0.2 版本统一存 Web）
created_at String ISO 8601 创建时间戳

注意： 创建时 项目名 == 文件夹名，但以后可以通过修改 .kitty_project.json 解耦显示名和文件夹名。

四、技术实现要点

1. SAF 权限持久化：
   ```kotlin
   context.contentResolver.takePersistableUriPermission(
       uri,
       Intent.FLAG_GRANT_READ_URI_PERMISSION or Intent.FLAG_GRANT_WRITE_URI_PERMISSION
   )
   ```
   必须调用，否则重启 App 后失去文件访问权。
2. DocumentFile 操作：
   使用 DocumentFile.fromTreeUri() 进行目录遍历、创建文件/文件夹、读写内容。
3. 数据模型：
   · ProjectInfo：内存中管理的项目元数据
   · ProjectFile：文件树节点，含名称、URI、类型（文本/图片/其他）
   · RecentProjectRecord：包含项目名、URI字符串、最后打开时间
4. UI 状态管理：
   使用 ViewModel 管理项目加载状态、文件树列表、当前打开文件内容，避免在 Composable 里直接搞业务逻辑。
